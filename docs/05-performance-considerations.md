# Performance Considerations

## Target

The assessment targets approximately 10,000 employees.

## Employee APIs

Search, filtering, and pagination are server-side so the browser does
not load all employees at once.

Recommended production indexes should cover employee identifiers,
department relationships, country filtering, and salary
employee/effective-date lookups.

## Salary

Current salary uses the latest effective salary record. The
employee/effective-date uniqueness constraint prevents duplicate
records.

## Statistics

Statistics are generated by the backend. For substantially larger
datasets, more aggregation can be pushed into SQL and expensive
statistics can be cached.

## Frontend

-   Request only required employee pages.
-   Avoid rendering thousands of rows.
-   Reuse shared styling variables.
-   Avoid unnecessary API calls.

## Future Scaling

1.  Move statistics aggregation further into SQL.
2.  Validate indexes with execution plans.
3.  Cache expensive organization-wide statistics.
4.  Add observability for API/database latency.
5.  Introduce asynchronous analytics processing if required.
